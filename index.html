第2回勉強会では、Gitの基本操作からGitHubを使ったPull Request、 コンフリクト解消、レビューの流れまでを、実務で使う形に近づけて学びます。

01 Git基礎

add / commit / status / log など、最低限必要な操作を理解する。

Theme

この勉強会で押さえること

Git

変更履歴を管理する

ファイルの変更内容を記録し、いつ・誰が・何を変更したのかを追跡できるようにします。

Hub

チームで共有する

GitHubを使ってソースコードを共有し、Pull Requestを通じてレビューとマージを行います。

PR

レビュー文化を理解する

自分の変更を説明し、他者のレビューを受けて、品質を高める流れを学びます。

Agenda

当日の学習メニュー

01

Gitとは何か

バージョン管理、ローカルリポジトリ、コミットの考え方を理解します。

02

基本コマンド

status / add / commit / log / diff / restore など、よく使う操作を確認します。

03

GitHubへpush

ローカルの変更をGitHubへ反映し、リモートリポジトリの役割を理解します。

04

ブランチとPull Request

featureブランチを作成し、Pull Requestを作ってレビューの流れを体験します。

05

コンフリクト解消

同じファイルを複数人で変更したときの衝突を、実際に解消します。

Commands

最低限覚えるGitコマンド

コマンドカードをクリックするとコピーできます。

Flow

実務で使う基本フロー

STEP 1

ブランチ作成

mainから作業用ブランチを切り、作業範囲を分離します。

STEP 2

修正・コミット

変更内容を小さく分けて、意味のある単位でコミットします。

STEP 3

Push・PR作成

GitHubへpushし、Pull Requestで変更内容を説明します。

STEP 4

レビュー・マージ

レビューを受け、修正後にmainへ反映します。

Entry

Gitを「なんとなく」から「使える」へ。

今回のゴールは、GitHubにpushできるだけではありません。 チーム開発で必要なPull Request、レビュー、コンフリクト対応まで理解することです。
